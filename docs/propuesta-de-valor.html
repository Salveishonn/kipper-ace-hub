Introducción

Contexto del Proyecto

Kipper Seguros es una organización de productores de seguros especializados que actúa como intermediaria entre productores asesores de seguros (PAS) y la compañía aseguradora Federación Patronal. El objetivo de este proyecto es construir una plataforma digital propia que centralice las herramientas de trabajo de los productores, refuerce la identidad de marca y habilite canales de comunicación 24/7 con asegurados.

El proyecto parte de un sitio web existente cuyo diseño visual y branding son correctos y se conservan íntegramente. Se descarta la funcionalidad de gestión compleja (CRM, sincronización con FedPat, gestión de pólizas/siniestros) en favor de un conjunto acotado y de alto valor para el productor.

Alcance · V1

¿Qué incluye esta propuesta?

Sitio Web Público (se conserva el diseño existente)

Todas las páginas públicas se portan al nuevo repositorio manteniendo el diseño, colores y branding actuales: landing principal, seguros (auto, moto, hogar, comercio, accidentes personales, vida), servicios, nosotros, comunidad, academy, contacto y cotizar.

Portal de Productores — 4 funciones principales

🎓

Kipper Academy

Videos de formación embebidos desde YouTube/Vimeo. Módulos y lecciones administrables por el equipo de Kipper.

📦

Material de Producción

Biblioteca de contenido para redes sociales (stories, posts, reels, guías). Descarga real desde almacenamiento seguro en la nube.

📅

Reserva de Cowork

Calendario de slots disponibles en la oficina de Ingeniero Maschwitz. Reserva y cancelación en tiempo real por parte del productor.

👤

Mi Perfil

Datos personales y de contacto del productor. Foto de perfil. Cambio de contraseña.

Panel de Administración (equipo Kipper)

Interfaz privada para gestionar el contenido del portal sin necesidad de acceso técnico: subir materiales, crear y publicar lecciones de Academy, administrar slots de cowork y gestionar usuarios productores.

Cotizador Online (widget Federación Patronal)

Integración del widget HTML provisto por Federación Patronal en la página de cotización. El cálculo de precios corre íntegramente del lado de la aseguradora — sin lógica de negocio adicional para Kipper.

Bot de WhatsApp — Botmaker + Federación Patronal

Atención 24/7 vía WhatsApp para productores y asegurados. El bot se conecta directamente a las APIs de Federación Patronal (conexión ya existente del lado de la aseguradora). Kipper sólo aporta el webhook para consultas de cowork (reservas, disponibilidad) y la configuración de los flujos conversacionales en Botmaker.

Lo que queda para V2 (mejoras futuras): Portal web de asegurados (ver pólizas, pagos online), inventario de productos por productor, notificaciones push, integración directa con FedPat para gestión de cartera, app móvil.
Tecnología

Stack Tecnológico

La elección tecnológica prioriza la reutilización del trabajo ya realizado (diseño 100% conservado), la seguridad de los datos y la capacidad de escalar sin cambiar de plataforma.

Capa Tecnología Por qué esta elección
Frontend React 18 + TypeScript + Vite + Tailwind CSS El diseño y los componentes ya están construidos. Reutilizar ahorra 4–6 semanas de trabajo.
Base de datos PostgreSQL 16 (gestionado por Supabase) Motor robusto con ACID compliance. Backups automáticos diarios. SOC 2 Type 2.
Autenticación Supabase Auth (JWT + verificación por email) Sistema battle-tested. No requiere construir auth desde cero. Roles: admin y productor.
Seguridad de datos Row Level Security (RLS) en PostgreSQL El acceso se controla a nivel de base de datos — incluso un bug en el código no puede filtrar datos entre usuarios.
Archivos Supabase Storage (S3-compatible) Almacenamiento de materiales, PDFs y avatares con políticas de acceso por usuario.
Tiempo real Supabase Realtime (WebSocket) Disponibilidad de slots de cowork actualizada en vivo para todos los productores conectados.
WhatsApp Bot Botmaker + API Federación Patronal Fed. Patronal ya tiene la conexión construida. Kipper configura flujos y aporta webhook para cowork.
¿Por qué no .NET + Angular o Node.js + Prisma desde cero?
El diseño completo ya está en React — rehacerlo en Angular implicaría rediseñar todo desde cero. Supabase es PostgreSQL gestionado: agregar un backend Node.js + Prisma por encima replica lo que Supabase ya provee (auth, almacenamiento, tiempo real, seguridad) sin ganancia funcional a esta escala.
Arquitectura

Diagrama de Infraestructura

Usuario (navegador / WhatsApp) │ ▼ Cloudflare ── DNS + DDoS + TLS 1.3 + CDN global │ ├──▶ Cloudflare Pages (Frontend React) │ SPA estática · sin servidor de origen · 99.99% uptime │ └──▶ Supabase Cloud (Backend) ├─ PostgreSQL 16 (datos, RLS, backups automáticos) ├─ Auth (JWT, verificación email, roles) ├─ Storage (materiales, avatares, PDFs) ├─ Realtime (WebSocket para cowork en vivo) └─ Edge Functions (webhook Botmaker → cowork) Usuario WhatsApp │ ▼ Botmaker Platform ├──▶ Federación Patronal API (pólizas, pagos, coberturas) └──▶ Supabase Edge Function (reservas cowork de Kipper)

Atributos de Calidad

Atributo Cómo se garantiza
Escalabilidad Supabase escala conexiones y almacenamiento de forma independiente. Cloudflare CDN absorbe picos de tráfico automáticamente. La arquitectura modular permite agregar el portal de asegurados o FedPat sync sin afectar lo existente.
Disponibilidad Supabase Pro: 99.9% SLA con failover automático. Cloudflare Pages: 99.99%+. Frontend y backend son independientes — un incidente en Supabase no baja el sitio público.
Seguridad RLS en PostgreSQL: el acceso se controla a nivel de base de datos. HTTPS obligatorio vía Cloudflare. Supabase certificado SOC 2 Type 2. Tokens de API de Fed. Patronal nunca expuestos al frontend. Políticas de storage por usuario.

Opciones de Hosting

Se presentan tres opciones de alojamiento. La diferencia principal es el nivel de control técnico versus simplicidad operativa.

Opción A — Todo gestionado Opción B — Híbrido Opción C — Self-hosted
Frontend Cloudflare Pages (gratis) Hetzner VPS CX21 + nginx Hetzner VPS CX31 + nginx
Backend Supabase Pro Supabase Pro Supabase self-hosted (Docker)
Costo mensual (infra) ~USD 25/mes ~USD 33/mes ~USD 15–20/mes + tiempo técnico
Backups Automáticos diarios Automáticos diarios Deben configurarse manualmente
Carga operativa Ninguna Baja Alta (parches, monitoreo, seguridad)
Recomendado para Inicio y crecimiento Cuando se necesite una API propia Capacidad DevOps dedicada
Nota sobre Opción C: No se recomienda para una organización que maneja datos sensibles sin capacidad técnica dedicada. Un backup mal configurado o un servidor sin parchear puede derivar en incidentes legales graves.
Recomendación: Opción B — Híbrido. El servidor VPS de Hetzner permite alojar APIs propias y lógica de negocio personalizada además del frontend, manteniendo Supabase Pro como backend gestionado. Ofrece el equilibrio óptimo entre control técnico, costo y confiabilidad operativa.

Fase 1 — Fundación

Nuevo repositorio, proyecto Supabase limpio, CI/CD a Cloudflare Pages, dominio kipperseguros.com configurado.

Todas las páginas de landing, seguros por ramo, formularios de contacto y cotización.

Semana 4

Fase 3 — Auth + Portal Shell

Login, registro, recuperación de contraseña, navegación del portal de productores, seguridad por roles.

Semana 7

Fase 5 — Material de Producción

Integración con Supabase Storage, descargas reales, panel de subida para el equipo de Kipper.

Semanas 8–10

Fase 6 — Reserva de Cowork

Base de datos de slots y reservas, calendario UI, flujo de reserva/cancelación, disponibilidad en tiempo real (Realtime WebSocket), vista de administrador.

Semana 11

Fase 7 — Mi Perfil + Panel Admin

Edición de perfil con guardado real, subida de avatar, gestión de usuarios en el admin.

Semana 12

Fase 8 — QA y Lanzamiento

Testing end-to-end, auditoría de seguridad (RLS), optimización de rendimiento, deploy a producción.

Semana 12.5

Fase 9 — Cotizador Widget

Recepción e integración del HTML embed de Fed. Patronal en /cotizar, adaptación visual, testing mobile.

Semanas 13–14

Fase 10 — Bot de WhatsApp (Botmaker)

Coordinación con Fed. Patronal sobre API del bot existente, Edge Function de Kipper para cowork, configuración de flujos en Botmaker (productores y asegurados), QA en sandbox de WhatsApp.

Acuerdo y Firma

La firma de este documento implica la aceptación de los términos, alcance y condiciones descritos en esta propuesta.

Términos y Condiciones

1. Alcance: El desarrollo incluye exclusivamente las funcionalidades descritas en la sección "¿Qué incluye esta propuesta?" (V1). Cualquier funcionalidad adicional se presupuestará por separado a la tarifa horaria acordada.

2. Forma de pago: Se acordará entre las partes el esquema de pago único o dividido. El inicio del trabajo queda condicionado al pago del primer tramo.

3. Abono mensual: El servicio de mantenimiento comienza al momento del lanzamiento en producción. El abono cubre los conceptos detallados en el desglose mensual. No incluye el costo de plataformas de terceros (Botmaker, Supabase, Cloudflare).

4. Propiedad del código: Al completar el pago del desarrollo, el cliente recibe la titularidad completa del código fuente y el acceso a todos los repositorios y servicios asociados.

5. Confidencialidad: Ambas partes se comprometen a mantener la confidencialidad de la información compartida durante el desarrollo del proyecto.

6. Cronograma: Los plazos estimados son referenciales y están sujetos a la disponibilidad oportuna de materiales, credenciales y feedback por parte del cliente. Demoras en la entrega de insumos (widget Fed. Patronal, acceso Botmaker) pueden extender el plazo proporcionalmente.
